## الفصل 0 — القواعد الملزمة (تسبق كل خطة)

1. **معمارية MVC صارمة:** المنطق في `models/` و`lib/services/` فقط، التوجيه في `controllers/` والمسارات في `modules/api/*/routes.ts`. يُمنع منطق أعمال داخل ملفات الصفحات أو main.ts.
2. **OOP احترافية:** كل نموذج يرث `BaseModel`، كل متحكم يرث `BaseController`. لا استعلامات SQL مباشرة خارج Models (أي استثناء يجب توثيقه في WORKLOG).
3. **i18n إلزامي:** يُمنع أي نص ظاهر للمستخدم خارج دالة `t()` / `translations`. أي نص جديد يدخل `src/i18n/ar.ts` و`en.ts` معاً. البنية مهيأة لإضافة لغات جديدة بلا تعديل كود.
4. **قاعدة البيانات:** كل تغيير مخطط عبر migration مرقّمة `00XX_*.sql`. يُمنع تعديل migrations قديمة أو الاستعلام عن أعمدة غير موجودة فيها.
5. **الوضع الليلي + RTL/LTR + إتاحة الوصول (a11y)** إلزامية في كل UI جديد (`dark:` variants, aria-labels, تباين عالٍ).
6. **لا نصوص ثابتة ولا أرقام سحرية** — الثوابت في `config/`.
7. **التوثيق المصاحب إلزامي:**
   - `WORKLOG.md` (جذر المشروع): سجل زمني لكل تغيير بصيغة
     `[YYYY-MM-DD] [P?-T??] — ماذا تغير / لماذا / الملفات / من نفذ / حالة الاختبار`
   - `PLAN-STATUS.md`: لوحة حالة كل المهام (`☐ لم تبدأ / 🔧 جارية / ✅ مكتملة ومختبرة / ⛔ معطلة`)
   - لا تُعتبر المهمة "مكتملة" إلا بعد تسجيلها في الملفين معاً واجتياز اختبار القبول.

## الفصل 3 — الخطة 1️⃣: الإصلاح الحال

### T1.1 ترحيل `0007_schema_alignment.sql`
- إضافة: `users.elo_rating INTEGER DEFAULT 1500`، `competitions.winner_id INTEGER`، `competitions.average_rating REAL DEFAULT 0`، فهارس مناسبة.
- استبدال كل مراجع `user_follows` بـ `follows` (المواقع المؤكدة: `UserModel.ts:229`, `SearchModel.ts:256`, `UserSettingsModel.ts:211`).
- **الاختبار:** `npm run db:migrate:local` ثم تشغيل متابعة مستخدم وبحث دون أخطاء SQL.
- **القبول:** صفر إشارة لـ `user_follows` في `src/`.

### T1.2 ربط الوحدات اليتيمة في main.ts
تركيب: `recommendations`, `leaderboard`, `analytics` (ad-blocks/ad-reports مؤجلة للخطة 4).
- **الاختبار:** طلب HTTP لكل نقطة يرجع JSON وليس 404.
- **القبول:** `docs/03-API-REFERENCE.md` محدث بحالة كل مسار.

### T1.3 إصلاح استقبال البث (حي + بعد الانتهاء)
تشخيص وإصلاح المسار: تسجيل chunks ← `/chunks/register` (BUG-11: منع الخصم من الرفع) ← الدمج عند المضيف ← VOD للمشاهد بعد انتهاء البث.
- **الاختبار:** منافسة تجريبية بمضيف وخصم ومشاهد؛ تحقق من البث الحي ثم إعادة المشاهدة بعد النهاية.
- **القبول:** المشاهد يشاهد أثناء الحي وبعد النهاية بدون انقطاع أو شاشة فارغة.

### T1.4 أمان حرج
| البند | الحل |
|-------|------|
| SHA-256 بدون salt | PBKDF2 عبر WebCrypto (≥100k دورة) + salt عشوائي + مقارنة آمنة زمنياً |
| زر الحظر الزائف (BUG-12) | تعديل `users.is_active = 0` + تدمير جلسات المستخدم + رفض authMiddleware |
| XSS | تنقية مدخلات التعليقات/المنافسات من HTML/JS |
| انهيار التسجيل (BUG-14) | try/catch حول EmailService — فشل البريد لا يمنع التسجيل |

- **القبول:** مستخدم محظور ترفض جميع جلساته 403؛ تسجيل ببريد مقطوع يكتمل.

### T1.5 دورة النهاية والأرباح
عند `POST /api/competitions/:id/end`: حساب متوسط التقييمات ← تعيين `winner_id` ← `EloRatingService.updateRatings()` ← `LivePayoutEngine.finalizePayouts()` تلقائياً بالنسبة الصحيحة (لا 50/50 أعمى) ← قفل ضد التنفيذ المزدوج (BUG-04).
- **الاختبار:** منافسة تجريبية بتقييمات مختلفة ← القسمة صحيحة في `user_earnings`.
- **القبول:** لا أرباح معلقة للأبد؛ إعادة نداء end لا تكرر التنفيذ.

## الفصل 4 — الخطة 2️⃣: المفقودات من الواقع الحالي

### T2.1 مودال الدعوات الكامل (أولوية قصوى)
1. فتح تلقائي فور إنشاء منافسة بلا منافس (redirect لصفحة المنافسة مع `?invite=1`)
2. بطاقة hover غنية لكل منافس: تقييماته، عدد منافساته، انتصاراته/خسائره، المجالات التي نافس فيها (تفعيل `/api/recommendations/competitor-stats/:userId`) + رابط للبروفايل
3. فحص `user_settings.allow_requests` وقائمة الحظر → عرض "الطلبات مغلقة" بدل زر الدعوة
4. بحث داخلي + تعدد دعوات + إغلاق/فتح متكرر (موجود جزئياً) مع تعطيل نهائي عند: ربط منافس / دخول بث / حذف المنافسة
- **القبول:** السيناريو كاملاً يعمل يدوياً بلا أخطاء كونسول.

### T2.2 الإشعارات الفورية الشاملة
- سيرفر: `EventPusher.publish()` على قناة `user:<id>` عند: دعوة جديدة، قبول/رفض (للمضيف)، طلب انضمام، قرار الطلب.
- عميل: خدمة `SseService` جديدة في `client/services` — اتصال دائم بقناة `user:<id>`، إعادة اتصال تلقائية بـ Last-Event-Id، تحديث badge فوري، Toast فوري.
- نقر إشعار دعوة ← انتقال مباشر لصفحة المنافسة مع لوحة قرار (انضم كمُنافس / شاهد / ارفض).
- **الاختبار:** متصفحان — A يدعي B → Toast فوري لدى B دون refresh؛ قبول B → إشعار فوري للمضيف A.
- **القبول:** صفر اعتماد على التحديث اليدوي لتلقي الدعوات.

### T2.3 عرض المنافسات المقترحة
تفعيل RecommendationEngine في الرئيسية/explore بأوزان: اللغة > البلد > المتابَعون > الأحدث > الأكثر مشاهدة > الأعلى تقييماً > اهتمامات المستخدم (`user_keywords`)، مع infinite scroll وتدهور رشيق (Graceful degradation — لا جدار "0 نتائج" أبداً).
- **القبول:** مستخدمان بخصائص مختلفة يريان ترتيباً مختلفاً منطقياً.

### T2.4 التعليقات والتقييمات
تقييم 0–100 أثناء البث الحي فقط، حساب المتوسط، منع التقييم المزدوج، ربط النتيجة بالفائز (تكامل T1.5)، تعليقات محفوظة مع VOD.
- **القبول:** تقييمات المشاهدين تحدد المنتصر فعلياً وتظهر في سجل المنافسة.
