## منطق الترتيب

الترتيب هنا يخالف البديهة في موضع واحد، وله سبب هندسي:

```
المرحلة 0  تثبيت خط الأساس          2–3 أيام
المرحلة 1  إيقاف نزيف المال          2–3 أيام     ← موضعي، عاجل
المرحلة 2  شبكة الأمان (اختبارات)    1–2 أسبوع    ← تسبق بقية الأمان
المرحلة 3  المصادقة والجلسات         4–6 أيام     ← يلمس 113 مساراً
المرحلة 4  الوقت الحقيقي والبث       1–2 أسبوع
المرحلة 5  صلابة دورة المنافسة       2–3 أسابيع
المرحلة 6  المال الكامل والشفافية    1–2 أسبوع
المرحلة 7  الإدارة والسلامة          5–8 أيام
المرحلة 8  UX والعولمة وPWA          1–2 أسبوع
المرحلة 9  الجاهزية الإنتاجية        4–7 أيام
```

**لماذا الاختبارات (2) قبل المصادقة (3)؟**
نقل الجلسة إلى الكوكيز يلمس كل مسار يعتمد المصادقة (113 مساراً). بلا اختبارات، هذا التغيير يكسر المنصة **بصمت** — لا خطأ بناء، لا خطأ أنواع، فقط مستخدمون لا يستطيعون الدخول.

**لماذا المال (1) قبل الاختبارات (2)؟**
`SEC-01` و`SEC-02` تفقدان المال **الآن**، وإصلاحهما موضعي (ملفان). الانتظار أسبوعين لبناء شبكة الأمان يعني أسبوعين إضافيين من التعرّض. لكن **الاختبار الأحمر يُكتب قبل الإصلاح** (انظر `13-TEST-STRATEGY.md` §8).

**النظافة المعمارية (265 استعلاماً) ليست مرحلة.** تُنفَّذ انتهازياً: أي ملف تلمسه لسبب آخر، تُخرج SQL منه. حملة تنظيف بلا اختبارات = إدخال أخطاء بلا شبكة أمان.

## المرحلة 0 — تثبيت خط الأساس
**المدة:** 2–3 أيام

1. فرع `stabilization` من `main`.
2. **نسخة احتياطية من D1 الإنتاجية** + إجراء استعادة **مُجرَّب** (النسخة غير المُجرَّبة ليست نسخة).
3. فصل بيئات development / staging / production بمتغيّرات منفصلة.
4. إصلاح `db:reset` — PowerShell يمنع أي CI (`package.json`).
5. توليد الجرد: `node dev-tools/route-inventory.mjs`.
6. **تصحيح `PLAN-STATUS.md`:** كل `✅` تخصّ منطقاً بلا اختبار تُخفَّض إلى `🧪`.
7. تصحيح التناقضات: أوامر `README` الوهمية، `docs/04-STREAMING-PIPELINE.md` المفقود، وحدات `AGENTS.md` المذكورة كغير مربوطة وهي مربوطة.

**بوابة الخروج:**
- [ ] استعادة D1 مُجرَّبة فعلياً
- [ ] `npm run db:reset` يعمل على Linux
- [ ] لا مرجع إلى ملف غير موجود
- [ ] `PLAN-STATUS.md` يعكس الواقع
- [ ] الجرد مولَّد ومراجَع

## المرحلة 3 — المصادقة والجلسات
**المدة:** 4–6 أيام | **شرط مسبق:** المرحلة 2 مكتملة

بالترتيب — كل خطوة تُقلّل مخاطرة التي تليها:

1. **SEC-07** توحيد مفتاح الجلسة (`sessionId` / `session_id`) — يُصلح خروج لوحتي الأدمن والمعلن.
2. **SEC-06** توليد عشوائي آمن (يشمل رمز CSRF).
3. **SEC-05** تقييد CORS بقائمة بيضاء.
4. **SEC-13** إحكام مصفوفة الصلاحيات — يُعيد `payment-methods` و`ad-blocks` للعمل.
5. **SEC-08** كوكي HttpOnly + تدوير الجلسة + CSRF حقيقي (على مراحل).
6. **SEC-09** حذف `unsafe-eval` (`unsafe-inline` بخطة موثّقة).
7. **SEC-12** rate limiting موزَّع عبر D1 + WAF.
8. **SEC-15** ترقية الاعتماديات على دفعات.

**بوابة الخروج:**
- [ ] `grep -rn "localStorage.*[sS]ession" src/` ⇒ صفر
- [ ] `window.sessionId` محذوف
- [ ] الرمز لا يظهر في أي جسم استجابة
- [ ] 11 محاولة دخول ⇒ 429 (يصمد عبر طلبات منفصلة)
- [ ] الأدوار السبعة تعمل E2E بالكوكيز
- [ ] `npm audit` صفر `high` في الإنتاج
- [ ] وسيلة دفع تُضاف بنجاح (إثبات إصلاح الميزة المعطّلة)

## المرحلة 4 — الوقت الحقيقي والبث

**بوابة الخروج:**

## المرحلة 6 — المال الكامل والشفافية
**المدة:** 1–2 أسبوع

1. Stripe كاملاً في staging ثم production.
2. PayPal: يُنفَّذ فعلياً أو يُحذف من الواجهة.
3. **ترحيل الحقول المالية من `REAL` إلى `INTEGER` بالسنت** — الفاصلة العائمة تُراكم أخطاء تقريب حقيقية.
4. تعريف العملات والتحويل والتقريب صراحةً.
5. فصل: الإيراد الإجمالي، رسوم البوابة، حصة المنصة، حصة المشاركين، المتاح، المعلّق.
6. `financial_ledger` مزدوج القيد وغير قابل للتعديل.
7. معالجة refund وchargeback.
8. تنفيذ السحب الفعلي (لا تغيير حالة فقط).
9. مطابقة يومية مع Stripe.
10. متطلبات الهوية والضرائب حسب الدول المستهدفة.

**بوابة الخروج:**
- [ ] مجموع القيود = صفر حسابياً دائماً
- [ ] إعادة أي webhook لا تكرّر المال

## المرحلة 8 — UX والعولمة وPWA
**المدة:** 1–2 أسبوع

1. تدقيق RTL/LTR شامل.
2. **316 نص fallback إنجليزي** إلى i18n (`grep -rho "tr\.[a-zA-Z_]* ||" src | wc -l`).

**بوابة الخروج:**
- [ ] Lighthouse جوال ≥ 85 أداء، ≥ 95 accessibility
